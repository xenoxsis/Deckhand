    The panel on a tablet

    The same panel, drawn in a tablet's browser and reachable over your own network — so the control surface can sit beside the laptop instead of on top of its screen. The work still happens on the laptop; the tablet only ever supplies the tap.

    Setting it up

    1. Write a token

    Every request needs it, and what's on the other side of it launches and types things as administrator — so it wants to be long and random rather than memorable. It lives in a file outside the project, one line, nothing else:

    Sixteen characters is the enforced minimum; the status window says token too short and refuses to serve below it. Don't put the token in dashboard.json — that file travels with the project, so a token in it ends up in every copy, backup and build output.

    In dashboard.local.json, so the setting stays with the machine rather than the project:

    That makes startup ask "on this laptop, or on a tablet?" — it doesn't force anything. Start with --remote to skip the question, which is what a pinned shortcut wants:

    The first start opens a Windows Firewall prompt for the port. Allow it on private networks.

    3. Scan the QR

    The status window on the laptop lists the addresses the tablet can use and shows the first of them as a QR code. Press Show to reveal the token, and the QR grows to carry it too: scanning is then the whole of the setup, because the page stores the token and scrubs it out of the address bar.

    The token rides in the URL fragment (#token=…), which browsers never send to the server — so it doesn't appear in any request, log or proxy on the way. Masked again, the QR encodes only the address, which keeps Show the one switch that reveals the secret.

    Typing it by hand instead

    Open http://<address>:8787/ on the tablet and paste the token into the box the page shows. It's kept in the browser's local storage from then on, so this is a once-per-tablet job.

    The status window

    In tablet mode this small ordinary window is all that's on the laptop's screen. The panel behind it is still built, still watches which app is focused and still does all the work — it just isn't drawn here.

    What it showsWhy it's there
    Addresses, and the first as a QR+ in the listen prefix isn't something you can type into a tablet, so it's expanded into this machine's real addresses — interfaces with a default gateway first, since a WSL, Hyper-V or VPN-stub address is one nothing else on the network can reach. All are listed anyway, because guessing wrong shouldn't hide the one that works.
    The token, masked until ShowAlso names where the token came from, so "is it reading my file?" is answerable without an experiment.
    Whether the tablet is getting through, and which oneA coloured dot plus the paired device's short id and the address it last called from.
    Whether the tablet is keeping its own screen awakeThe page reports what it managed on every request — see keeping the screen on.
    How big the tablet's screen turned out to beThe page measures its own visible viewport and the box the tiles are laid out in, and sends both on every request — this is the one thing about the tablet the laptop can't work out for itself. In CSS pixels, with the device-pixel ratio beside them, so a tablet sold as 2560×1600 reads 1280×800. The tiles pair is the one to put in the designer's screen size; the log writes a line whenever either changes.
    A log of everything between the two sidesTaps, rejections, reloads, pairing. The same log the panel keeps.

    Its buttons

    • Design — opens the layout designer, the same window --designer starts with. It's here because in this mode the panel being designed isn't on any screen to right-click. Its SCREEN boxes arrive filled in with what this tablet reported, so the preview is at the size the tablet really draws. The tablet stays paired while it's open, and saving reaches the panel as an ordinary reload — so the layout appears on the tablet as you arrange it. Taps are refused while the designer has focus, for the same reason they are while this window has it.
    • Unpair — lets go of the paired device so another one with the right token can take the session. For swapping tablets without re-reading anything.
    • ↻ Reload — re-reads the config and restarts the server, which also unpairs. Use it after moving to another Wi-Fi: it re-reads the addresses too.
    • Quit — stops the server and ends the process. If the designer has unsaved work it asks first, and Cancel there cancels the quit.
    • ✕ — doesn't quit. It hides the window to the notification area and the panel goes on serving. Hover the tray icon for the same status line, double-click to bring the window back, right-click for the designer, Reload and Quit.
    The tray icon starts out hidden

    Windows 11 hides tray icons it hasn't been told about, so the first time you press ✕ the icon lands behind the ^ chevron. Drag it onto the taskbar to keep it there. A notification appears either way, since ✕ everywhere else means gone.

    Why a name needs permission and an address doesn't

    Anyone can point a hostname at your machine and have a page of theirs talk to the panel from inside its own origin. An address can't be moved like that. So names are listed rather than accepted, and a request calling this machine anything not listed is refused.

    Installing the page on the tablet

    The page can go on the tablet's home screen and open as an app rather than as a browser tab: its own icon, no address bar, the whole screen given to tiles. Nothing about how it works changes — a control surface you reach through a tab list is a control surface with two taps in front of it, and an address bar is 40 wasted pixels across a panel sized to fit exactly.

    • iPad / Safari — Share → Add to Home Screen.
    • Android / Chrome — menu → Add to Home screen or Install app.

    The laptop serves the manifest, the icons and a service worker alongside the page, so the shell is cached and a launch is instant. When you rebuild the app with a changed page, the open tab replaces itself — the cache is named after the build. With the laptop stopped, a launch still comes up from cache with the connection dot red; with nothing cached, you get the laptop isn't answering and a Try again button rather than the browser's own error page, which in a window with no address bar would be a dead end.

    When the laptop isn't answering

    The dot in the header turns red and every tile dims and stops responding. A tile that still looks live while nothing is listening is one you tap twice and then harder, so the page would rather show you it has nothing to send to. The banner says it in words as well, since a dimmed tile doesn't distinguish a laptop asleep from one on another network.

    Being refused counts as not answering — the tap would be refused too — so the rule stays a single one: red dot, dead tiles, banner for the reason. The groups still scroll, so the panel can be read while it's out of touch, and the page knocks every three seconds; the first answer that arrives brings everything back.

    Changing the token drops the tablet on purpose. Whether you press New in the status window, edit the token file, or point the panel at a different one, the server restarts — which lets go of the parked long poll — and the next request comes back 401. The page discards the token it was holding rather than retrying with it, and returns to the token box quoting what the laptop said. Scan the QR again with Show on to pair it back.

    Keeping the tablet's screen on

    A panel that goes black after 30 seconds isn't a panel. The page asks for a screen wake lock; where that isn't available it falls back to playing a tiny muted looping video, which most platforms accept as a reason to stay awake. It reports which it managed on every request, so the laptop's status window and log say so too:

    • screen kept awake — a real wake lock.
    • best effort — the video fallback.
    • may sleep — neither worked; set the tablet's own screen timeout instead.

    What stops it being a remote shell

    The honest summary: this opens a port that can fire your own tiles as administrator. That is worth understanding rather than trusting, so here is exactly what the protocol can and can't express.

    Ids only

    A request can name a tile that is already configured and already on screen. There is no field anywhere in the protocol that carries a path, a command, or text to type. The worst a request can do is fire one of your own tiles — there is no "run this" to reach for, because no such message exists.

    The ids are content-addressed hashes rebuilt with every snapshot, so an id can only ever name a tile that was on screen when the tablet last drew.

    Pictures by content, never by path

    A tile that wears a picture sends the tablet the hash of that picture's bytes, not where the file is. The request that comes back for it is answered out of the set the panel published with those tiles, so there is no filename in it to sanitise and nothing outside that set to name: /api/icon/../../dashboard.json is refused for the same reason a made-up hash is — neither is a key in the table. The reply says "not on the panel" rather than "no such file", which would otherwise be a way to ask the laptop what it has.

    The bytes are behind the token like everything else. That's why the page fetches them itself instead of leaving it to the browser: an <img src> can't be made to send a header, so it would have meant a way in without one.

    The same tap, not a second implementation

    The server raises the click on that very button in the panel. Nothing about what a tile does is reimplemented over HTTP, so the two can't drift apart: URL tiles still pick the focused browser, deElevate still de-elevates, an app tile's wide side still asks which window.

    A token on every call

    Hashed and compared in constant time, so a wrong token leaks nothing about how wrong it was. Sixteen characters is the enforced minimum and the server refuses to start below it.

    One device at a time

    The page generates an id for itself once and keeps it; the session pins to that rather than to an address, so a new DHCP lease or a different Wi-Fi doesn't bounce your own tablet, and "second device refused" still means something behind a tunnel where every client shares one address. Unpair is how you hand the session over.

    Guessing is rationed per address

    Ten wrong tokens from one address inside a minute locks that address out for a minute — so someone spraying guesses can only lock themselves out, and can't deny your tablet its own first pairing. The table of addresses is capped, so cycling through addresses grows nothing.

    Names are allow-listed, bodies are capped

    A request calling the machine a name that isn't allowed is refused, and a request body is capped at a kilobyte — an id is 16 characters.

    A tap can be refused for being untimely

    While one of the dashboard's own windows has focus, a tap is refused: the panel would otherwise send keystrokes to itself. While the window picker is open, a tap for anything behind it comes back with a conflict and the picker stays put — the same answer a finger on the panel gets, since the modal covers those tiles there too.

    It's plain HTTP on your own network

    There is no TLS here: anyone who can watch the traffic between the tablet and the laptop can read the token. That's an acceptable trade on a home or office network you control, and the reason the default is off, the port is only opened when asked, and the whole protocol is built so the token buys nothing but your own tiles. For anything crossing a network you don't control, listen on loopback only and put a tunnel (Tailscale, an SSH forward) in front — then list the name it arrives as in allowedHosts.

    Why the tablet keeps up

    The page holds one request open at a time. When there's nothing new, the laptop parks it for up to 25 seconds and releases it the instant the panel publishes something — so a focus change or an expanded tile lands on the tablet immediately, and the tablet's radio wakes for one answer instead of for a poll every second. A parked request counts as "seen just now", so the connection dot doesn't flicker during quiet stretches.

    Troubleshooting

    SymptomLikely cause
    The page doesn't load at allWrong address — try the others the status window lists; a WSL or VPN address can't be reached from the network. Otherwise the firewall prompt was dismissed, or another program holds port 8787.
    not serving — token too shortThe token file is missing, empty, or under 16 characters. The status window names the file it read.
    Taps do nothing, page looks fineCheck the laptop's log. A tap while one of the dashboard's own windows has focus is refused by design — click into your work first.
    Another device is pairedPress Unpair on the laptop, then reload the page on the tablet.
    Every request refused for a minuteTen wrong tokens from that address inside a minute. Wait it out and check the token.
    The tablet shows an old set of tilesIts page is older than the build. Reloading picks up the new one; the service worker does it by itself when it next reaches the laptop.
    Tiles never change when you switch appsThe sections may not be written for profiles at all. The panel's context label — shown on the tablet too — names what it thinks is focused.
    The tablet's screen keeps sleepingmay sleep in the status window: neither wake method worked. Set the tablet's own screen timeout.
