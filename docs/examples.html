    Example configs

    Five complete files, each one a whole dashboard.json you can save and run. They're invented rather than borrowed from anyone's real panel, so the paths, labels and commands are all yours to replace.

    Trying one

    Copy it over your dashboard.json and save. The panel reloads itself about half a second later. If a group doesn't appear, the app it's written for probably isn't focused — the panel's top-left strip names the profile it currently sees. Run Deckhand.exe --check to have every mistake in the file listed at once.

    1. Starter

    The smallest thing worth having: a handful of apps and snippets, always on screen, no grid placement to think about. The apps and snippets shorthand each become one section on their own.

    Shows: the shorthand lists, a program tile, a folder tile, a URL tile, {date}, and method: "type".

    2. A writer's desk

    Two apps that each get their own strip of the panel, plus a set of snippets that are always there. The mail and document groups are pinned to the same rectangle: they belong to different profiles, so only one is ever drawn and they can't collide.

    Shows: a coarse 8×8 grid, two profiles sharing one rectangle, an always-visible section below them, {date}/{time}/{clipboard}, multi-line snippets, tile colours, and span.

    3. A developer's panel

    A left rail of apps, a middle strip that changes with the focused window, and a self-maintaining list of projects down the right — generated from a directory, not written out by hand.

    Shows: four profiles, editor snippet expansion via keys, terminal snippets with "method": "type" and "keys": "enter", a source section with a ▾ command list, and a URL tile pinned to one browser.

    Two sources over one directory

    Nothing stops several sections scanning the same folder — each gets its own scan. Here one types into a terminal and one opens folders in Explorer, and which you get depends on what you were doing when you reached for the panel.

    They're given different labels deliberately: which side of a ⇆ switch a section is showing is remembered against its label, so two source sections sharing one label also share their switch side.

    4. A support desk

    Canned replies for the mail client, portal links for the browser, and a folder of open cases with a human-readable title under each — read from a file some other script keeps up to date.

    Shows: split with a capture group feeding {id}, matchLabel/otherLabel, subtitles, an always-visible source with no command, and allowedHosts left empty.

    5. A folder launcher

    No profiles, no typing, nothing conditional: three lists of folders that keep themselves up to date, for a machine where the job is mostly "open the right folder". Good on a shared workstation, and the whole file is short enough to read in one go.

    Shows: a small grid, several sources over different roots, %USERPROFILE% expansion, a section with columns omitted so its tiles flow instead of snapping, and tilesPerRow on a wide group.

    A local overlay for any of them

    Whichever of the above you start from, anything machine-specific belongs in a dashboard.local.json beside it rather than in the file itself. Keys here win, objects merge a level at a time, and a list replaces the shared one outright.
